# NFC 출석

학생: `/attend/index.html` · 교사: `/attend/admin.html`

학생이 책상 NFC 주소를 열면 등록된 브라우저 토큰으로 출석을 확인합니다. 실제 NFC 스캔 여부나 물리적 기기 자체를 증명하는 방식은 아니며, 기존 시간·위치 제한 설정은 유지합니다.

## 교사 사용

1. 명단 탭에서 학년도를 선택하고 학번·이름을 붙여넣어 **변경 미리보기 → 적용**합니다. 구글 시트를 원본으로 관리할 때는 [시트 연결 안내](sheets/README.md)를 따릅니다.
2. 등록코드 안내문을 인쇄해 학생에게 전달합니다. 추가 등록을 열었을 때 자가 등록한 학생은 **명단 확정** 전까지 출석 처리되지 않습니다.
3. 출석 현황에서 출석·지각·인정·결석 확정·미확인을 관리합니다. 행이 없으면 미확인이고 결석은 교사가 확정합니다. 정정 사유·교사·시각·전후 값이 남으며 원래 태그 시각은 보존합니다.
4. 출석 또는 지각한 학생은 **이동 처리**에서 외출(복귀 예정 필수)·복귀·조퇴를 확인합니다. 반복 외출을 지원합니다. 조퇴는 등교 기록을 덮어쓰지 않습니다.
5. 잘못 누른 이동은 **직전 이동 취소**로 되돌립니다. 예를 들어 외출→조퇴→조퇴 취소는 외출 상태로 돌아옵니다. 취소 이벤트도 보존합니다.
6. NFC 재태그는 외출·조퇴를 해제하지 않습니다. 해당 상태나 결석·인정 확정 뒤 재태그하면 교사 화면에 확인 시각을 표시합니다. 미확인은 태그 시 정상 출석 판정을 다시 수행합니다.
7. 출석 대상일은 기본 월~금입니다. 방학·공휴일·학년별 예외를 별도로 설정하세요. 학년별 설정이 전체 설정보다 우선합니다.

## 명단과 기록 보존

- 학생 UUID와 기기 등록은 학번과 분리됩니다. 학년도는 3월부터 다음 해 2월까지입니다.
- 진급은 같은 UUID로 새 학년도 명단에 등록합니다. 같은 학번을 다른 학년도에 새 학생이 써도 기록이 합쳐지지 않습니다.
- 전출·졸업은 삭제 대신 상태와 마지막 출석 대상일을 지정합니다. 시작·종료일 모두 포함하며 종료일까지는 출석할 수 있습니다.
- 시트 누락은 삭제로 해석하지 않습니다. 미리보기는 30분 동안 유효하고, 서버나 시트가 바뀌면 재확인해야 합니다. 행별 버전은 오래된 시트가 웹 수정 내용을 되돌리는 것을 막습니다.
- 현재 한 학생의 학년도별 재적 구간은 1개입니다. 같은 해의 전출 후 재전입(여러 구간)이나 같은 해 학번 재사용은 자동 처리하지 않습니다. 과거 구간을 임의로 늘려 덮어쓰지 마세요.
- 학생·출석·이동·정정 이력을 직접 삭제하는 UI와 테이블 쓰기 권한은 없습니다. 사유를 남기는 교사 RPC로 처리합니다.

## 개발·검증

`supabase/migrations/20261027051543_attendance_roster_movements.sql`은 v1 스키마에서 v2로 확장하는 일회성 마이그레이션입니다. 기존 데이터·기기 해시는 유지하고 학번 FK의 연쇄 삭제를 제거합니다.

테스트는 운영 계정·데이터를 사용하지 않습니다.

```sh
cd attend/tests
npm ci
node database.mjs
node interface.mjs
```

`baseline.sql`과 `baseline-functions.sql`은 데이터 없는 v1 테스트 스키마입니다. 공개키는 클라이언트 설정에, 시트 연결 비밀값은 Apps Script 사용자 속성에만 저장합니다. 연결 코드·학생 명단·개인 기록을 저장소에 커밋하지 않습니다.
