# NFC 출석

학생: `/attend/index.html` · 교사: `/attend/admin.html`

학생이 책상 NFC 주소를 열면 등록된 브라우저 토큰으로 출석을 확인합니다. 실제 NFC 스캔 여부나 물리적 기기 자체를 증명하는 방식은 아니며, 기존 시간·위치 제한 설정은 유지합니다.

## 교사 사용

1. 명단 탭에서 학년도를 선택하고 학번·이름을 붙여넣어 **변경 미리보기 → 적용**합니다. 구글 시트를 원본으로 관리할 때는 [시트 연결 안내](sheets/README.md)를 따릅니다.
2. 등록코드 안내문을 인쇄해 학생에게 전달합니다. 추가 등록을 열었을 때 자가 등록한 학생은 **명단 확정**에서 출석 시작일과 사유를 확인하기 전까지 출석 처리되지 않습니다. 시작일 기본값은 오늘이며, 승인 전 태그 시도는 따로 남지만 출석으로 자동 확정되지 않습니다. 잘못된 자가가입은 **가입 거절**로 학번·기기 연결을 해제합니다. 학생 식별자와 태그 시도·거절 사유는 보존되며 **가입 거절 이력**에서 확인할 수 있습니다.
3. 대시보드의 학생별 출석 현황에서 출석·지각·인정·결석 확정·미확인을 관리합니다. 행이 없으면 미확인이고 결석은 교사가 확정합니다. 정정 사유·교사·시각·전후 값이 남으며 원래 태그 시각은 보존합니다.
4. 출석 또는 지각한 학생은 **이동 처리**에서 외출(복귀 예정 필수)·복귀·조퇴를 확인합니다. 반복 외출을 지원합니다. 조퇴는 등교 기록을 덮어쓰지 않습니다.
5. 잘못 누른 이동은 **직전 이동 취소**로 되돌립니다. 예를 들어 외출→조퇴→조퇴 취소는 외출 상태로 돌아옵니다. 취소 이벤트도 보존합니다. 취소 후 실제의 더 이른 시각으로 다시 입력할 수 있으며, 아직 유효한 직전 이동보다 이른 시각은 거부합니다.
6. NFC 재태그는 외출·조퇴를 해제하지 않습니다. 해당 상태나 결석·인정 확정 뒤 재태그하면 교사 화면에 확인 시각을 표시합니다. 미확인은 태그 시 시간·위치 제한을 다시 확인합니다. 원래 태그 시각이 있으면 그 시각으로 출석/지각을 판정해 표시 시각과 일치시킵니다.
7. 출석 대상일은 기본 월~금입니다. 방학·공휴일·학년별 예외를 별도로 설정하세요. 학년별 설정이 전체 설정보다 우선합니다.

## 대시보드

- 날짜와 반을 선택하면 출석 대상·출석·지각·미확인·인정·결석 확정·외출 중·조퇴를 한눈에 확인합니다. 카드를 누르면 이름 검색을 초기화하고 해당 학생 목록을 엽니다.
- 숫자와 확인 진행은 날짜·반 기준이며 이름 검색·상태 필터 때문에 바뀌지 않습니다. 외출·조퇴는 등교 기록과 별도로 집계합니다. 대상 외에 남아 있는 기존 기록은 목록에서 구분해 표시합니다.
- 먼저 확인할 학생은 복귀 지연, 외출 중, 미확인 순서로 최대 5명을 보여줍니다. 미확인은 자동 결석이 아닙니다. 오늘 화면은 20초마다 갱신하며 입력 창을 열거나 다른 탭을 보고 있을 때는 자동 갱신하지 않습니다.
- 휴대폰 없는 학생: **휴대폰 없이 출석 처리 → 이름·학번 검색 → 교사 출석 확인 → 출석/지각 선택 → 사유 입력 → 저장**. 버튼을 열기만 해서는 기록되지 않습니다. 별도의 휴대폰 미소지 표시나 일괄 처리는 없습니다.
- 휴대폰·PC 브라우저 모두 교사 화면을 사용할 수 있습니다. 구글 시트의 사용자 정의 메뉴는 별개이며 컴퓨터의 웹 구글 시트에서 사용합니다.

## 명단과 기록 보존

- 학생 UUID와 기기 등록은 학번과 분리됩니다. 학년도는 3월부터 다음 해 2월까지입니다.
- 새 학년도 명단은 2월 중 준비해 적용하세요. 3월 1일부터 새 학년도 명단이 있어야 출석할 수 있습니다. 진급은 같은 UUID로 새 학년도 명단에 등록합니다. 같은 학번을 다른 학년도에 새 학생이 써도 기록이 합쳐지지 않습니다.
- 전출·졸업은 삭제 대신 상태와 마지막 출석 대상일을 지정합니다. 시작·종료일 모두 포함하며 종료일까지는 출석할 수 있습니다.
- 시트 누락은 삭제로 해석하지 않습니다. 미리보기는 30분 동안 유효하고, 명단 내용이나 시트 입력이 바뀌면 재확인해야 합니다. 등록 실패·기기 등록·코드 재발급만으로는 미리보기가 무효화되지 않습니다. 행별 버전은 오래된 시트가 웹 수정 내용을 되돌리는 것을 막습니다.
- 현재 한 학생의 학년도별 재적 구간은 1개입니다. 같은 해의 전출 후 재전입(여러 구간)이나 같은 해 학번 재사용·두 학생의 학번 맞바꾸기는 자동 처리하지 않습니다. 오등록 자가가입의 거절만 학번을 다시 사용할 수 있게 합니다. 과거 구간을 임의로 늘려 덮어쓰지 마세요.
- 학생·출석·이동·정정 이력을 직접 삭제하는 UI와 테이블 쓰기 권한은 없습니다. 사유를 남기는 교사 RPC로 처리합니다.

## 개발·검증

`supabase/migrations/20261027051543_attendance_roster_movements.sql`은 v1 스키마에서 v2로 확장하는 일회성 마이그레이션입니다. 기존 데이터·기기 해시는 유지하고 학번 FK의 연쇄 삭제를 제거합니다.

테스트는 운영 계정·데이터를 사용하지 않습니다.

```sh
cd attend/tests
npm ci
node database.mjs
node interface.mjs
node dashboard.mjs
node sessions.mjs
node session-interface.mjs
node review-regressions.mjs
node sheets.mjs
```

`baseline.sql`과 `baseline-functions.sql`은 데이터 없는 v1 테스트 스키마입니다. 공개키는 클라이언트 설정에, 시트 연결 비밀값은 Apps Script 사용자 속성에만 저장합니다. 연결 코드·학생 명단·개인 기록을 저장소에 커밋하지 않습니다.

후속 마이그레이션 `20261027070831_attendance_review_fixes.sql`은 최초 v2 다음에 적용합니다. 배포 전 기존 미리보기는 다시 생성하세요. 승인 대기 학생을 시트에서 재적으로 바꿀 때에는 출석 시작일을 명시하고 경고를 확인해야 합니다. 전출·졸업은 마지막 대상일을 경고에 표시하므로 학년말 기본값을 그대로 두지 않았는지 확인하세요.


## 수업·교시별 출석

교사 화면의 **수업 출석 → 반복 시간표 설정 → 시간표 추가**에서 수업명(예: 화학, 점심 후 확인), 교시·회차 표시, 반복 요일, 접수 시작·지각 시작·마감, 적용 기간을 설정합니다. 반 일괄 선택과 학생 개별 선택을 함께 쓸 수 있어 이동수업에도 대응합니다. 각 학생의 수강 기간도 지정합니다. 같은 시간에 여러 수업에 속한 학생은 회차 카드에 겹침 경고가 표시됩니다.

- 시간은 한국 시각이며 **접수 시작 ≤ 지각 시작 < 마감**입니다. 지각 시작 시각부터 지각, 마감 시각부터 접수 불가입니다.
- 오늘 회차는 교사 수업 화면 조회 또는 해당 학생의 출석 선택 화면 조회 때 한 번만 자동 생성됩니다. 별도 예약이나 추가 과금 서비스는 없습니다. 그날 아무도 조회하지 않은 수업의 과거 회차는 자동으로 소급 생성하지 않습니다. 빠진 회차는 **이 날짜만 수업 추가**로 교사가 만들 수 있습니다.
- 회차가 만들어질 때 명단·이름·학번·시간을 복사하여 보존합니다. 시간표 수정/중지는 이미 만들어진 회차를 바꾸지 않습니다. **오늘 회차도 이미 생성됐다면 회차 설정/명단 조정/휴강에서 따로 처리**하세요.
- 반 일괄 선택은 현재 학생 UID를 선택합니다. 이후 전입생은 자동으로 수강 명단에 들어오지 않습니다. 수강생 추가·제외 및 각 학생 수강 기간을 다시 확인하세요. 한 시간표에서 같은 학생의 수강 기간은 하나이며 중간 공백이 필요하면 시간표를 나눠 만드세요. 다음 학년도 시간표는 새 학년도 학생 명단을 적용한 뒤 새로 만듭니다.
- **이 날짜만 수업 추가**는 보강·임시 수업·추가 점검에 사용합니다. 휴업일 수업은 명시적으로 허용해야 합니다. 자동 시간표는 재적 기간과 학년별 출석 대상일을 따릅니다.
- 회차의 시간 변경은 출석 처리가 한 건도 없을 때만 허용됩니다. 기록이 있는 회차의 시간이 잘못되었으면 휴강하고 별도 회차를 만드세요. 휴강은 기록을 지우지 않으며 다시 접수로 바꿀 수 있습니다. 마감 시각이 지난 회차는 접수 상태를 다시 열어도 학생 태그를 받지 않습니다.
- 회차 명단에서 제외한 학생도 기록은 유지되며 **대상 제외 기록** 필터에서 확인할 수 있습니다. 복원하면 기존 상태가 다시 집계됩니다. 오늘 명단 조정은 반복 시간표 명단을 바꾸지 않습니다.

학생은 기존 NFC 주소에서 **등교 또는 수업을 하나 선택**합니다. 페이지를 여는 것만으로는 출석을 기록하지 않습니다. 선택 수업의 기록만 저장되며 등교·다른 교시·외출·조퇴는 바뀌지 않습니다. 휴대폰이 없는 학생은 교사가 수업을 선택하고 학생별 **교사 확인**에서 상태와 사유를 저장합니다.

- 등교가 미확인이어도 수업 출석은 기록할 수 있고, 등교 미확인 안내를 표시합니다. 등교 기록은 별도로 확인합니다.
- 외출 중·조퇴·등교 결석/인정 확정 상태의 수업 태그는 거절하고 시도 이력을 남깁니다. 교사가 이동·등교 상황을 먼저 확인합니다. 자동 복귀·자동 결석은 없습니다.
- 수업 태그마다 해당 회차 시간과 기존 학교 반경 설정을 검사합니다. GPS나 NFC 주소는 교실에 실제 있는지를 증명하지 않으며 기존 학교 반경까지만 확인합니다.
- 첫 태그 시각은 보존됩니다. 교사의 모든 정정은 사유·시각·교사·전후 상태를 남기며 재태그로 덮어쓰지 않습니다. 교사가 미확인으로 돌린 경우에도 교사가 다시 확인해야 합니다.
- 교사 권한 범위는 기존과 같습니다. 등록 교사 전원이 수업과 기록을 관리할 수 있으며 담당 교사별 분리는 없습니다. 학생용 API는 토큰 소유자의 수업 선택지만 제공합니다.

**수업 기록 CSV 받기**와 구글 시트의 **기간별 수업 출석 가져오기**는 최대 62일을 조회합니다. 시트의 **수업 출석** 탭은 조회용이며 수정 내용을 서버에 적용하지 않습니다. 기존 명단·등교·이동 탭과 분리되어 있고 휴강·대상 제외 여부를 표시합니다. 기존 Apps Script 사용자는 최신 Code.gs로 교체해야 새 메뉴가 생깁니다. 연결 코드는 기존 사용자 속성을 그대로 사용합니다.

마이그레이션 `20261027114301_class_attendance_sessions.sql`은 일일 등교 테이블을 이관하거나 지우지 않고 수업용 테이블·RPC를 추가합니다. 운영 적용 전 PGlite 격리 테스트와 UI 모의 테스트로 권한, 중복, 날짜/시간 경계, 기록 보존, 두 종류 출석의 독립성을 확인합니다.

시간표의 **중지** 버튼은 수강생 전원이 더 이상 승인 명단에 없어도 사용할 수 있습니다. 새 회차 생성만 중지하며 기존 회차는 별도로 휴강 처리합니다.

운영 안내: **NFC를 연 뒤 등교 또는 수업 버튼을 눌러야 출석됩니다.** 학생에게 변경된 절차를 안내하세요. 등교의 출석 기준은 기존 분 단위 설정(해당 분까지)을 유지하고, 수업은 표시된 지각 시작 시각부터 지각입니다.

시간이 겹친 수업은 점검 용도일 수도 있으므로 출석을 일괄 차단하지 않습니다. 실제로 같은 학생의 겹친 두 회차에 출석·지각이 있으면 양쪽 학생 목록과 학생 결과 화면에 경고합니다. 교사가 확인해 잘못 선택한 회차를 정정하세요. 교사 정정 후 재태그와 대상 제외 후 태그도 별도 시도 이력으로 표시합니다.
